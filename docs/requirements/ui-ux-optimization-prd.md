## 1. 项目背景

BloodLine-Analysis 是一个面向 Kettle `.repo` 文件与 Java 源码目录的数据血缘分析工具，当前聚焦对象级与表级血缘、影响分析、闭环分析和 Web 查询体验。前端基于 React + Vite + React Flow 构建，提供扫描控制、对象搜索、血缘图可视化、影响分析和闭环分析等核心能力。

随着功能迭代，前端页面在信息架构、交互设计和性能表现上逐渐暴露出可优化空间。本文档系统梳理当前页面展现形式的问题，并提出可落地的优化需求，以提升用户体验和系统可维护性。

---

## 2. 优化目标

1. **提升信息可读性**：减少页面垂直堆叠导致的视觉疲劳，引入分层信息架构（标签页、折叠面板）。
2. **消除冗余展示**：移除重复或低价值的内容区域，避免用户在不同可视化形式间困惑。
3. **增强交互反馈**：为扫描、搜索、图渲染等耗时操作提供明确的进度与状态反馈。
4. **修复样式与可访问性缺陷**：补全缺失的 CSS 定义，优化色彩语义和键盘/屏幕阅读器支持。
5. **改善性能与扩展性**：减少客户端全量过滤，引入分页、缓存和虚拟化机制。

## 4. 详细需求说明

### 4.1 全局导航与布局优化

#### 需求 G-1：当前路由高亮
**问题描述**：`AppLayout` 顶部导航链接只有 hover 样式，没有当前页高亮，用户无法直观判断自己在哪个模块。

**优化方案**：
- 为当前激活的导航链接添加底部边框或背景高亮。
- 添加 `aria-current="page"` 属性以支持屏幕阅读器。

**验收标准**：
- [ ] 用户处于"对象列表"页时，顶部"对象列表"链接有明显的激活态视觉样式。
- [ ] 页面刷新后高亮状态正确恢复。

---

#### 需求 G-2：面包屑动态生成与显示名优化
**问题描述**：面包屑逻辑使用硬编码 `if` 链维护（`useBreadcrumbs`），新增路由需改组件；详情页面包屑显示 `table:users` 而非"用户表"。

**优化方案**：
- 将路由配置抽取为常量映射表（包含路径、标题、动态参数解析规则），面包屑根据当前路径和映射表自动生成。
- 当面包屑包含对象详情时，异步获取 `display_name` 并替换原始 `tableKey`。

**验收标准**：
- [ ] 新增页面只需修改路由映射表，无需改动 `AppLayout.tsx`。
- [ ] 详情页面包屑显示对象的 `display_name`（若加载失败则回退到 `key`）。

---

### 4.2 首页（TableSearchPage）优化

#### 需求 H-1：统计卡片计算缓存
**问题描述**：统计卡片（总数、Job 数、Transformation 数等）在每次渲染时都对 `catalogItems` 执行多次 `.filter()`，对象数量过千时产生明显卡顿。

**优化方案**：
- 使用 `useMemo` 缓存各统计值，仅在 `catalogItems` 变化时重新计算。
- 如后续统计维度增加，考虑将统计计算下沉到后端 API。

**验收标准**：
- [ ] 快速输入搜索关键字或在页面内触发其他 state 变更时，统计卡片区域不重新计算过滤逻辑。
- [ ] 通过 React DevTools Profiler 验证 `TableSearchPage` 的渲染耗时显著降低。

---

#### 需求 H-2：搜索交互增强
**问题描述**：搜索按钮无加载态，点击后用户不知道请求是否已发出；无清空按钮；搜索预览面板出现在结果列表下方，长列表时用户看不到预览。

**优化方案**：
- 搜索按钮在请求期间显示加载 spinner 并禁用。
- 搜索框右侧添加"×"清空按钮，一键重置输入和结果。
- 点击"预览"后，自动滚动预览图到可视区域（`scrollIntoView`）。

**验收标准**：
- [ ] 网络延迟时搜索按钮有明显 loading 状态。
- [ ] 存在搜索内容时，输入框右侧出现可点击的清空图标。
- [ ] 点击任意结果的"预览"后，预览图区域平滑滚动至屏幕中央。

---

#### 需求 H-3：搜索结果显示 `display_name`
**问题描述**：搜索结果列表只展示 `item.name`，但 API 已返回 `display_name`，对于中文用户 `display_name` 更具可读性。

**优化方案**：
- 搜索结果主标题优先展示 `display_name`；若与 `name` 不同，可在第二行以小字展示 `name`。

**验收标准**：
- [ ] 搜索结果项可见 `display_name`。
- [ ] `display_name` 为空时回退到 `name`。

---

### 4.3 扫描控制面板（ScanControlPanel）优化

#### 需求 S-1：扫描状态轮询
**问题描述**：点击"重新扫描解析"后，UI 将状态设为"运行中"，但不再更新。扫描可能持续数分钟，用户只能手动刷新页面确认是否完成。

**优化方案**：
- 当最新扫描记录状态为 `running` 时，启动定时轮询（建议每 3 秒调用 `fetchLatestScanRun()`）。
- 状态变为 `completed` 或 `failed` 时停止轮询，并给出明确反馈：
  - 完成：提示"扫描完成"并刷新首页数据。
  - 失败：提示"扫描失败"并引导至失败汇总页。

**验收标准**：
- [ ] 扫描运行期间，面板状态每 3 秒自动更新。
- [ ] 扫描完成后，面板显示最终结果并触发一次全局数据刷新（或 Toast 提示）。
- [ ] 组件卸载时清除轮询定时器，避免内存泄漏。

---

#### 需求 S-2：扫描状态样式解耦
**问题描述**：扫描状态使用中文作为 CSS 类后缀（`scan-status-已完成`、`scan-status-运行中`），文案调整会直接导致样式失效。

**优化方案**：
- 使用稳定的状态 key（`running`、`completed`、`failed`）映射到 CSS class 和显示文案，两者解耦。

**验收标准**：
- [ ] 修改状态显示文案不影响样式类名。
- [ ] 后端新增未知状态时有默认样式兜底。

---

### 4.4 对象详情页（TableDetailPage）优化

#### 需求 D-1：移除或折叠冗余的血缘列表
**问题描述**：详情页同时展示 `ConnectedLineageGraph`（交互式完整血缘图）和 `LineageGraph`（静态三列文字血缘）。两者信息重叠，文字列表不仅无增量价值，还会把下方内容推离首屏。

**优化方案**：
- **首选方案**：移除 `LineageGraph` 组件，将详情页的焦点完全放在 `ConnectedLineageGraph` 上。
- **备选方案**：若业务方坚持保留列表视图，将其折叠在"切换为列表视图"的标签/按钮后，默认隐藏。

**验收标准**：
- [ ] 详情页不再默认展示与血缘图重复的三列文字列表。
- [ ] 页面首屏高度显著降低，核心信息（元数据 + 血缘图）在首屏即可见。

---

#### 需求 D-2：详情页标签页重构
**问题描述**：元数据、完整链路图、关联对象、API 诊断等信息全部垂直堆叠，复杂对象页面非常长，用户需要在大量滚动中查找目标信息。

**优化方案**：
- 将详情页内容组织为标签页（Tab）结构，建议分为：
  - **血缘图**（默认）：`ConnectedLineageGraph` + `RelatedObjectsPanel`
  - **元数据**：对象基本信息 + `object_metadata` 字段列表 + `view_definition` SQL
  - **API 诊断**：未解析/降级原因列表
- 标签切换时保留已加载数据，避免重复请求。

**验收标准**：
- [ ] 详情页顶部出现可切换的标签栏，默认选中"血缘图"。
- [ ] 标签切换不触发页面刷新，切换动画流畅（<200ms）。
- [ ] 元数据标签中展示 `view_definition`（视图对象）和字段列表。

---

#### 需求 D-3：补全缺失的 CSS 定义
**问题描述**：`TableDetailPage` 使用了 `.metadata-summary`、`.api-diagnostics-list` 等 className，但 `styles.css` 中不存在对应定义，导致元数据和 API 诊断区域呈现为无样式的裸文本，视觉层级混乱。

**优化方案**：
- 为 `.metadata-summary` 定义卡片式布局（背景色、圆角、内边距、信息行网格）。
- 为 API 诊断列表定义清晰的行样式（左侧状态色条、标题、说明文字层级）。
- 全局扫描 JSX 中使用的所有 className，确保都有对应 CSS 定义。

**验收标准**：
- [ ] 元数据区域有清晰的视觉边界和层级。
- [ ] API 诊断列表不再复用 `failure-item` 样式，有独立的、语义正确的样式定义。
- [ ] 无浏览器开发者工具中的"Unknown property"或缺失样式警告。

---

#### 需求 D-4：关联对象面板增强
**问题描述**：`RelatedObjectsPanel` 中的关联对象按钮看起来像是普通文本，用户意识不到可点击；点击后仅高亮图节点，不能跳转到该对象详情页。

**优化方案**：
- 为关联对象项添加卡片/按钮样式（边框、背景、hover 效果）。
- 左侧添加对象类型图标/色块，帮助快速识别。
- 点击关联对象时，若该对象有独立详情页（如 `api_endpoint`、`java_module`），导航到对应详情页；若当前已在详情页且目标对象类型暂不支持详情页，则仅高亮图节点。

**验收标准**：
- [ ] 关联对象按钮具有明显的可点击 affordance。
- [ ] 可导航的关联对象点击后正确跳转，不可导航的保持现有高亮行为。

### 4.5 影响分析页（ImpactPage）优化

#### 需求 I-1：影响分析图可视化
**问题描述**：`ImpactPage` 目前仅展示按跳数分组的文字列表，对于血缘分析工具而言，缺少图可视化严重削弱了信息传达效率。

**优化方案**：
- 在 `ImpactPage` 顶部集成 `OverviewGraph` 或 `ConnectedLineageGraph` 组件。
- 图中以当前对象为中心，下游对象按跳数（hop）着色：
  - 第 1 跳：一种颜色
  - 第 2 跳：另一种颜色
  - 第 3 跳：第三种颜色
- 列表保留作为辅助视图，可折叠在图下方或侧边栏。

**验收标准**：
- [ ] 影响分析页展示以当前对象为起点的下游流向图。
- [ ] 图中节点按跳数进行颜色区分，图例清晰。
- [ ] 用户仍可查看文字版的分组列表（默认折叠或置于侧边）。

---

#### 需求 I-2：影响路径展示
**问题描述**：列表只告诉我某表是"第 3 跳"，但没有展示传播路径（A → B → C → D）。

**优化方案**：
- 在文字列表中，为每个受影响对象提供一条"影响路径"（用 `>` 连接的节点名称链）。
- 路径数据可通过后端已有的 BFS 逻辑扩展返回，或前端基于图结构临时计算。

**验收标准**：
- [ ] 文字列表中每个对象项展示至少一条从起点到该对象的影响路径。

---

### 4.6 闭环分析页（SelfLoopAnalysisPage）优化

#### 需求 C-1：命名统一（SelfLoop → CycleGroup）
**问题描述**：文件名为 `SelfLoopAnalysisPage.tsx`，路由为 `/analysis/cycles`，UI 标签为"闭环分析"。实际功能检测的是多表循环组，不是单表自环。命名不一致会导致维护困难和用户困惑。

**优化方案**：
- 将文件名 `SelfLoopAnalysisPage.tsx` 重命名为 `CycleAnalysisPage.tsx`（或 `CycleGroupAnalysisPage.tsx`）。
- 组件名、路由引用、面包屑文案统一调整为"闭环分析"/"Cycle Analysis"。
- 同步更新 `AGENTS.md` 或相关文档中的引用。

**验收标准**：
- [ ] 代码库中不再出现 `SelfLoop` 命名。
- [ ] 路由、导入、测试文件全部同步更新。

---

#### 需求 C-2：循环可视化
**问题描述**：闭环分析页仅列出循环组中的表名，用户无法直观看到循环边（A→B→C→A）。

**优化方案**：
- 为每个循环组提供一个小型 React Flow 子图，仅渲染该组涉及的节点和边。
- 子图可放在循环组卡片内，默认展开或提供"查看循环图"按钮。

**验收标准**：
- [ ] 每个闭环组可查看其拓扑结构图。
- [ ] 循环边使用明显颜色（如橙色/红色虚线）与普通血缘边区分。

---

#### 需求 C-3：循环严重度标识
**问题描述**：所有循环组都使用红色背景计数徽章，暗示它们都是"错误"，但某些循环可能是正常的业务逻辑。

**优化方案**：
- 根据循环长度或节点类型分配严重度标签：
  - 信息级（绿色）：2 节点简单循环
  - 警告级（黄色）：3-4 节点循环
  - 严重级（橙色）：5 节点以上循环
- 提供严重度图例说明。

**验收标准**：
- [ ] 循环组卡片展示严重度标签，颜色语义合理。
- [ ] 页面底部或顶部有严重度图例。

---

### 4.7 扫描失败汇总页（ScanFailureSummaryPage）优化

#### 需求 F-1：失败搜索与筛选
**问题描述**：当失败记录较多时，用户必须在多层嵌套的 `<details>` 中手动查找，没有搜索框、没有按失败类型/来源类型筛选。

**优化方案**：
- 在页面顶部增加搜索输入框，支持按文件名、失败消息、SQL 片段实时过滤。
- 增加筛选器：
  - 来源类型（Kettle / Java / MySQL 元数据）
  - 失败类型（解析错误 / 缺少引用 / 其他）
- 汇总卡片应根据后端返回的 `source_counts` 动态生成，而不是写死 `Kettle` / `Java` / `MySQL 元数据`。

**验收标准**：
- [ ] 输入搜索关键词后，失败列表实时过滤（前端过滤即可，无需后端接口改动）。
- [ ] 来源类型筛选器为动态生成的按钮/下拉框。
- [ ] 新增后端来源类型时，前端汇总卡片自动出现对应项。

---

#### 需求 F-2：失败记录可复制
**问题描述**：失败的 SQL 片段展示在 `<pre>` 块中，用户无法一键复制去本地调试。

**优化方案**：
- 为每个 SQL 片段 `<pre>` 块添加"复制"按钮。
- 复制成功后显示短暂 Toast 提示"已复制到剪贴板"。

**验收标准**：
- [ ] 每个 SQL 片段旁有可点击的复制按钮。
- [ ] 点击后内容成功写入系统剪贴板。

---

### 4.8 对象列表页（ObjectListPage）优化

#### 需求 O-1：服务端分页与可见筛选
**问题描述**：`ObjectListPage` 调用 `searchTables("")` 加载全部对象到浏览器内存，再通过 URL 参数 `?type=` 过滤。对象数量大时性能极差，且普通用户看不到类型筛选入口。

**优化方案**：
- **短期**：前端保留已有数据但增加虚拟滚动（`react-window` 或 CSS `content-visibility`），并在页面上方添加可见的类型筛选芯片（Chip）。
- **长期**：将分页和类型过滤下沉到后端 API（`GET /api/tables/search?page=&size=&type=`）。

**验收标准**：
- [ ] 对象列表页顶部出现可见的对象类型筛选芯片（全部 / 数据表 / 视图 / 源表 / API 端点 等）。
- [ ] 列表支持分页或虚拟滚动，1000+ 对象时滚动不卡顿。

---

### 4.9 图组件优化

#### 需求 R-1：图节点标签优先级
**问题描述**：`ConnectedLineageGraph` 优先显示 `technicalName`（如 `table:users`），`label`（如 `用户表`）作为小字 secondary。对于非技术用户，中文名称应更突出。

**优化方案**：
- 图节点主标签优先显示 `label` / `display_name`；若为空则回退到 `technicalName`。
- 技术名称以小字或 tooltip 形式展示。

**验收标准**：
- [ ] 详情页血缘图节点主标签为中文可读名称（当存在时）。

---

#### 需求 R-2：图加载骨架屏
**问题描述**：图加载期间仅显示纯文本"完整链路图加载中..."，面板高度塌陷，加载完成后页面发生明显布局跳动。

**优化方案**：
- 为图容器添加固定高度的骨架屏（shimmer/placeholder），高度与加载后的图区域一致（建议 400px）。

**验收标准**：
- [ ] 图加载期间占位区域高度稳定，加载完成后无布局跳动。

## 5. 非功能性需求

### 5.1 性能
- 首页统计卡片使用 `useMemo`，避免不必要的重计算。
- 对象列表页引入分页或虚拟滚动，渲染节点数控制在合理范围。
- 图组件在数据更新时自动 `fitView`，避免用户面对空白视口。

### 5.2 可访问性
- 所有导航链接添加 `aria-current="page"`。
- 扫描状态、失败类型、循环严重度不单独依赖颜色传递信息，需配合文字标签或图标。
- 为 CSS transitions 添加 `prefers-reduced-motion` 媒体查询支持。

### 5.3 样式规范
- 逐步将 `styles.css` 中的硬编码色值抽取为 `:root` CSS 自定义属性（设计令牌），至少覆盖：主色、成功色、警告色、错误色、背景色、文字色、圆角、间距阶梯。
- 禁止再使用中文作为 CSS 类名的一部分。
